# HERMICAD — پلتفرم هوش مهندسی ساختمان

ابزار تولید طرح و ترسیم مقدماتی، با تحلیل محدود و کنترل‌های داخلی/اظهاری. این کنترل‌ها تأیید ضوابط رسمی یا طراحی اجرایی نیستند.
برای بررسی بازتولید باید ورودی‌ها، نسخهٔ کامل پیاده‌سازی و وابستگی‌ها، تنظیمات و **seed** نگهداری شوند؛ شناسهٔ نسخه یا seed به‌تنهایی اثبات بازتولید نیست.

---

## اجرا در ۶۰ ثانیه

```bash
npm install
npm run dev          # http://localhost:3000
```

در **توسعهٔ محلی** اگر `DATABASE_URL` تعریف نشده باشد، برنامه از **PGlite**
(فایل‌محور در `.data/hermicad`) استفاده می‌کند. برای `npm start` در حالت production،
`DATABASE_URL` لازم است؛ فقط برای پیش‌نمایش/آزمون محلیِ تک‌فرایندی می‌توان صریحاً
`HERMICAD_ALLOW_PGLITE_IN_PRODUCTION=1` تنظیم کرد. این گزینه راهکار پایداری،
چندفرایندی، پشتیبان‌گیری یا انتشار عمومی نیست. ساختار جدول‌ها فعلاً هنگام نخستین
اتصال به‌صورت افزایشی bootstrap می‌شود؛ مهاجرت نسخه‌دار و بازیابی عملیاتی هنوز کامل نیست.

برای اجرا روی Postgres واقعی:

```bash
cp .env.example .env
# DATABASE_URL=postgresql://user:pass@host:5432/hermicad
npm run dev
```

### استقرار با Docker

```bash
docker compose up -d --build        # برنامه + Postgres، هر دو با healthcheck
HERMICAD_PUBLIC_URL=https://example.com POSTGRES_PASSWORD=... docker compose up -d --build
```

تصویر با کاربر غیر ریشه، فایل‌سیستم فقط‌خواندنی و `HEALTHCHECK` روی `/api/health`
اجرا می‌شود؛ چیدمان تصویر و دلیل نبودِ `output: standalone` در
[`docs/OPERATIONS.fa.md`](docs/OPERATIONS.fa.md).

پروژهٔ نمایشی مرجع را با دکمهٔ «ساخت پروژهٔ نمایشی» در `/projects` یا با:

```bash
curl -c hermicad.cookies -H 'Origin: http://localhost:3000' -X POST http://localhost:3000/api/projects/seed
# برای درخواست‌های بعدی همان فضای کار، از -b hermicad.cookies استفاده کنید.
```

بسازید؛ فایل کوکی را مانند گذرواژه محرمانه نگه دارید و در مخزن ثبت نکنید.

### استقرار پشت پراکسی TLS (ضروری برای انتشار عمومی)

اگر برنامه پشت پراکسیِ https اجرا می‌شود (پیش‌نمایش ابری، Nginx، CDN)، پراکسی باید
`Host` (یا `X-Forwarded-Host`) را بر اساس اتصال بیرونی بازنویسی کند. برنامه مبدأ
درخواست را با **هم‌میزانی** و نشانهٔ مرورگر (`Sec-Fetch-Site`) می‌سنجد و طرح‌واره
را فقط وقتی سخت می‌گیرد که پراکسی صریحاً https اعلام کند؛ جزئیات و دلیل در
[`docs/OPERATIONS.fa.md`](docs/OPERATIONS.fa.md).

سقف مصرف هر فضای کار با `HERMICAD_QUOTA_PROJECTS` (۲۰۰) و `HERMICAD_QUOTA_DESIGNS`
(۳۰۰) قابل تنظیم است تا یک بازدیدکننده نتواند پایگاه را پر کند. تاریخچهٔ اجراهای هر
پروژه هم با `HERMICAD_RUN_RETENTION` (۲۰) محدود می‌شود؛ اجرای فعال و رکوردهای پیش از
مهاجرت هرگز حذف نمی‌شوند. `HERMICAD_PUBLIC_URL` دامنهٔ `robots.txt`/`sitemap.xml` را
تعیین می‌کند. فهرست کامل متغیرها در [`.env.example`](.env.example).

| متغیر | پیش‌فرض | کار |
| --- | --- | --- |
| `DATABASE_URL` | — | پایگاه Postgres؛ در production الزامی (بدون آن ۵۰۳) |
| `HERMICAD_PUBLIC_URL` | میزبان درخواست | دامنهٔ عمومی برای robots/sitemap/متادیتا |
| `HERMICAD_QUOTA_PROJECTS` / `HERMICAD_QUOTA_DESIGNS` | ۲۰۰ / ۳۰۰ | سقف مصرف هر فضای کار |
| `HERMICAD_RUN_RETENTION` | ۲۰ | حداکثر اجراهای نگه‌داشته‌شدهٔ هر پروژه |
| `HERMICAD_QUALITY_TTL_MS` | ۱۵۰۰۰ | مدت کش نمایشی دروازهٔ کیفیت |

## اسکریپت‌ها

| دستور | کار |
| --- | --- |
| `npm run dev` | اجرای محیط توسعه |
| `npm run build` / `npm start` | بیلد و اجرای پروداکشن |
| `npm run typecheck` | بررسی تایپ‌ها (`tsc --noEmit`) |
| `npm run lint` | ESLint |
| `npm run test` | اجرای دروازهٔ کیفیت (بدون نیاز به دیتابیس) |
| `npm run test:http` | آزمون HTTP با سرور و پایگاه موقت؛ ابتدا `npm run build` اجرا شود |
| `npm run test:smoke` | دود-تست جریان کامل کاربر روی سرور در حال اجرا (`BASE=...`) |
| `npm run preview:design` | رندر همهٔ برگه‌های استودیو به PNG در `.preview/` برای بازبینی چشمی |

## نقشهٔ مسیرها

| مسیر | کار |
| --- | --- |
| `/` | نمای کلی قابلیت‌ها و جریان موتور |
| `/projects` | فهرست/ساخت پروژه |
| `/projects/[id]` | کارگاه: طرح‌ها، پلان، برگ‌های معماری، زمین، نیازمندی، اعتبارسنجی، تحلیل، خروجی |
| `/architecture` | معماری سیستم و مدل داده |
| `/design` | استودیو طراحی: فهرست سندها و ساخت سند نو |
| `/design/[id]` | محیط ترسیم آزاد (پلان) با کتابخانهٔ اشیا و خروجی SVG/PDF/DXF/XLSX/IFC/نما/برش |
| `/quality` | دروازهٔ کیفیت نرم‌افزار (اجرای زندهٔ آزمون‌ها؛ نه تأیید مهندسی) |
| `/scope` | پیش‌نویس دامنه، محدودیت‌ها و شواهد نرم‌افزاری؛ بدون ادعای تأیید یا انتشار |
| `/api/scope` | نسخهٔ JSON فقط‌خواندنی همین دفتر |
| `/api/*` | API پروژه، تولید، اصلاح، کنترل اولیه، نقشه، خروجی |
| `/robots.txt` | سیاست خزش: فقط مسیرهای عمومی، بدون `/api/`، `/share` و زیرمسیرهای فضای کار |
| `/sitemap.xml` | هشت مسیر عمومی با نشانی مطلق |

## ساختار کد

```
src/
  domain/        موتورهای خالص (بدون DB و UI) — قلب سیستم
    architecture/  موتور چیدمان و تولید پلان
    audit/         ممیزی هندسی
    drawing/       صحنه، SVG، DXF، PDF، برگه، جداول
    engineering/   رجیستری فرمول‌ها (واحد، اعتبار، محدودیت)
    exporters/     PDF/DXF/SVG/IFC/XLSX/CSV/JSON
    rules/         مستندات قواعد
    testing/       آزمون‌های قطعی + دروازهٔ کیفیت
  server/        لایهٔ دسترسی داده و سرویس‌ها
  app/           Next.js App Router (RSC + API routes)
  components/    UI (کارگاه، ویرایشگرها، استودیو)
  db/            Drizzle + بوت‌استرپ اسکیمای ایدمپوتنت (Postgres یا PGlite)
```

قاعدهٔ وابستگی یک‌طرفه است: **UI → API → موتور ← مدل مرکزی**. هیچ موتور دامنه‌ای
از دیتابیس یا UI ایمپورت نمی‌کند؛ به همین دلیل کل موتور در حافظه و در آزمون‌ها
قابل اجراست.

## استودیو طراحی

محیط ترسیم آزاد نقشه با کتابخانهٔ آمادهٔ **۱۷۷ شیء در ۲۰ دسته**، ویرایش زنده
(اندازه/چرخش/جابه‌جایی)، لایه‌بندی رشته‌ای و **۲۰ قالب خروجی**: SVG، PDF،
PDF چندبرگی (طبقه × رشته)، DXF پلان/نما/برش/**جزئیات**، XLSX متره و میلگرد،
IFC4، برگهٔ جزئیات سازه و جدول میلگرد، برگهٔ جداول و کیپلان، CSV/JSON.
جزئیات، وضعیت آزمون‌ها و محدودیت‌های صریح در [`docs/STUDIO.md`](docs/STUDIO.md).

```bash
npm test                  # دروازهٔ کیفیت (شامل سوئیت‌های استودیو)
npm run preview:design    # بازبینی چشمی همهٔ برگه‌ها → .preview/*.png
```

## محدودیت‌ها (مهم)

خروجی‌های HERMICAD **طرح مقدماتی/غربالگری** است، نه محاسبات اجرایی یا تأییدیهٔ
انطباق. مجموعهٔ آستانه‌های فعلی داخلی و تأییدنشده است و باید با ضوابط رسمی
تأییدشدهٔ حوزهٔ پروژه و تأیید مهندس دارای صلاحیت جایگزین شود. ثبت منبع و فرض
در بخش‌های موجود به معنی احراز رسمی آن‌ها یا کفایت مدارک پروژه نیست.
